# 📘 서버 배포 및 데이터 관리 매뉴얼 (Server Deployment & Data Management Guide)

본 매뉴얼은 **라벨 프린터 및 유통기한 관리 시스템**의 백엔드 서버 설치, 배포, 데이터 관리 및 클라이언트 단방향 동기화 매커니즘을 설명합니다.

---

## 1. 시스템 개요 및 동기화 구조

* **백엔드 스택**: Node.js, Express, SQLite3
* **단방향 동기화 방식 (Server-Master One-Way Sync)**:
  * **서버(Database)**가 단일 원본 마스터(Single Source of Truth)로 작동합니다.
  * 태블릿/클라이언트 앱은 시작 시(스플래시 화면) 및 동기화 요청 시 서버로부터 최신 데이터를 **다운로드만 수행**하며, 클라이언트의 로컬 변경사항이 서버 데이터를 오염시키지 않습니다.

---

## 2. 서버 배포 가이드 (Server Deployment)

### 2.1. 사전 준비 요구사항
* **Node.js**: v18.0.0 이상 설치
* **NPM**: v9.0.0 이상 설치

### 2.2. 소스 코드 다운로드 및 패키지 설치
```bash
# 1. 저장소 클론
git clone https://github.com/cgh88/label.git
cd label

# 2. 의존 패키지 설치
npm install
```

### 2.3. 환경 변수 설정 (`.env`)
프로덕션 환경 배포 시 프로젝트 루트 디렉터리에 `.env` 파일을 생성하고 보안 비밀번호를 설정합니다:

```env
PORT=3000
NODE_ENV=production
DEFAULT_ADMIN_PASSWORD=원하는_관리자_비밀번호
DEFAULT_STAFF_PASSWORD=원하는_직원_비밀번호
```

### 2.4. 서버 실행 방법

#### 개발 환경 실행 (Direct Run)
```bash
npm start
```
* 실행 후 웹 브라우저에서 `http://localhost:3000` 접속 확인

#### 프로덕션 환경 실행 (PM2 프로세스 관리자 사용)
서버가 24시간 중단 없이 실행되도록 PM2 프로세스 관리자를 권장합니다.

```bash
# 1. PM2 global 설치
npm install -g pm2

# 2. PM2로 서버 프로세스 시작
pm2 start ecosystem.config.js

# 3. 서버 상태 및 로그 확인
pm2 status
pm2 logs label-server

# 4. OS 재부팅 시 자동 실행 등록
pm2 startup
pm2 save
```

## 3. 서버 데이터 수정 및 관리 방법 (Data Management)

서버의 원재료 데이터, 카테고리, 보관위치별 유통기한은 아래 3가지 방법으로 수정 및 관리할 수 있습니다.

### 방법 1. 웹 관리자 대시보드를 통한 수정 (가장 추천하는 방법)

1. 웹 브라우저에서 `http://<서버_IP>:3000` 에 접속합니다.
2. 관리자 계정(`admin` / 설정한 비밀번호)으로 로그인합니다.
3. **[원재료 관리]** 탭에서:
   * **신규 원재료 추가**: 제품명, 카테고리, 약어를 입력하고 각 보관위치(해동, 메이크라인, 소스보틀 등)별 유통기한(일/시간)을 설정합니다.
   * **수정 및 삭제**: 기존 원재료 항목의 '수정' 또는 '삭제' 버튼을 눌러 즉시 변경합니다.
4. **결과**: 서버 데이터가 수정된 즉시 태블릿 앱이 접속할 때 최신 원재료 데이터가 단방향으로 다운로드됩니다.

---

### 방법 2. 엑셀(Excel) 파일 일괄 등록

1. 웹 관리자 대시보드의 **[원재료 관리]** 탭에서 `[샘플 엑셀 다운로드]` 버튼을 클릭하여 `SHELFLIFE_sample.xlsx` 양식을 받습니다.
2. 엑셀 파일에 카테고리, 제품명, 코드/약어, 보관위치별 유통기한 값을 작성합니다.
3. `[엑셀 업로드]` 버튼을 눌러 파일 선택 후 일괄 반영을 진행합니다.

---

### 방법 3. 기본 시드 데이터 파일 (`default_database.json`) 수정

1. 프로젝트 루트 디렉터리의 `default_database.json` 파일을 에디터로 엽니다.
2. `categories`, `storage_locations`, `label_sizes`, `ingredients_v2` 항목을 JSON 형식에 맞게 수정합니다.
3. 웹 관리자 화면의 **[기본값 초기화]** 기능(`POST /api/ingredients/reset`) 실행 시 해당 JSON 파일 내용으로 DB가 재초기화됩니다.

## 4. 단방향 동기화 검증 및 테스트 가이드

### 4.1. 단방향 동기화 테스트 절차

1. **서버 실행**: `npm start` 또는 PM2로 서버를 가동합니다.
2. **테스트 데이터 추가**:
   * 웹 브라우저(`http://localhost:3000`)에 접속하여 `[관리]` -> `[재료 추가]`에서 신규 테스트 원재료(예: `서버_테스트_원재료`)를 등록합니다.
3. **태블릿 앱 실행**:
   * 태블릿에서 앱을 실행하면 **스플래시 로딩 화면**에서 `서버 데이터 동기화 중...` 단계가 수행됩니다.
   * 메인 화면 진입 후 원재료 목록에 서버에서 추가한 `서버_테스트_원재료`가 자동으로 다운로드되어 나타나는지 확인합니다.
4. **단방향 검증**:
   * 태블릿 앱에서 데이터를 조회/사용하더라도 클라이언트 데이터가 서버로 역업로드(POST)되지 않으며, 서버의 원본 데이터베이스만 안전하게 유지됩니다.

## 5. 주요 API 명세

| 기능 | HTTP 메서드 | 엔드포인트 | 비고 |
| :--- | :--- | :--- | :--- |
| **로그인** | `POST` | `/api/auth/login` | 세션 쿠키 발급 |
| **데이터베이스 동기화** | `GET` | `/api/sync/database` | 전체 서버 DB 다운로드 (단방향) |
| **원재료 목록 조회** | `GET` | `/api/ingredients` | 원재료 및 보관 매핑 조회 |
| **원재료 추가** | `POST` | `/api/ingredients` | 관리자 권한 필요 |
| **원재료 수정** | `PUT` | `/api/ingredients/:oldName` | 관리자 권한 필요 |
| **원재료 삭제** | `DELETE` | `/api/ingredients/:name` | 관리자 권한 필요 |
